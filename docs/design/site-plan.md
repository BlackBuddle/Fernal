# Fernal 소개 페이지 디자인 계획

`docs/index.html` (GitHub Pages, https://blackbuddle.github.io/Fernal/) 의 계획과 점검 기록.

## 주제, 독자, 할 일

- 주제: 바탕화면 위 투명한 창에서 며칠에 걸쳐 자라는 3D 나무. Qt for Python(PySide6) 프로젝트.
- 독자: 프로젝트를 평가하는 같은 반 학생, 강사, PyQt 과제 심사자(어떻게 만들었는지), 그리고 직접 써 보려는 사람.
- 할 일: 1) 살아 있는 식물을 보여 주고 내려받게 한다. 2) Qt 기술과 성장 모델을 짧고 믿을 만하게 설명하고 보고서로 보낸다.

## 색

앱의 정체성(청자, 호박, 세이지, 감)을 그대로 쓴다. 모든 스크린샷의 배경은 불투명한 `#303030`이다.
이 회색을 그대로 무대로 쓰면 이미지 테두리가 사라져 나무가 실제 오버레이처럼 바탕 위에 떠 보인다.

| 이름 | hex | 쓰임 |
|---|---|---|
| 바탕화면 회색 | `#303030` | 스크린샷이 놓이는 어두운 띠(히어로, 테마, 내려받기). 스크린샷 배경과 같은 값 |
| 청자 종이 | `#E3E6DC` | 설명을 읽는 밝은 구간의 바탕. 크림이 아니라 회록빛 청자 유약 |
| 먹 | `#20251F` | 밝은 구간의 본문 |
| 청자 유약 | `#5A5F4B` / `#838675` | 보조 글자, 가는 선(앱의 glaze pool / celadon glaze) |
| 호박 | `#E2B65C` | 내려받기 버튼에만. 세계수의 빛나는 잎끝처럼 "빛나도 되는 단 하나" |
| 세이지 | `#8FBF7C` (어두운 띠) / `#3E6A33` (종이) | 링크와 키보드 포커스 |
| 감 | (페이지 색으로는 쓰지 않음) | 감색은 열매 나무 스크린샷 안에만 둔다. 아래 '뺀 장식' 참고 |

## 글꼴

- Noto Serif KR 500/600: 제목과 "식물의 목소리"(앱 도구창의 한 문장과 같은 역할). 행간 1.35.
- Noto Sans KR 400/500: 본문 17px, 행간 1.75, 한 줄 40자 안팎(최대 34em).
- 코드 식별자(`QQuickView` 등)만 시스템 고정폭(Consolas). 숫자나 라벨에는 쓰지 않는다.
- 비율: 14 / 17 / 21 / 28 / 44 / 76px.

## 배치

어두운 띠(화면에 보이는 것)와 청자 종이(어떻게 작동하는지)를 번갈아 둔다. 왼쪽 정렬, 가운데 정렬은 쓰지 않는다.

│      ,     ,@,      @@@                         @@@@@  @@@@@@@     @@@@@     │

┌ 청자 종이 ─ 돌보는 대로 자랍니다: 변수 6행(바뀌는 것, 측정 상관계수) + 식 3개 ──┐

모바일(360~820px): 제목 블록이 위, 성장 띠는 20, 50, 100% 세 단계만 보여 준다. 표는 쌓인 행이 된다.

## 원칙

- **기억에 남는 한 가지: 페이지를 가로질러 자라는 나무.** 같은 시드의 다섯 단계를 화분 높이를 맞춰 한 바탕에 세운다.
  각 칸의 폭을 나무 폭에 맞춰 잘라 작은 묘목은 좁게, 다 자란 나무는 넓게 둔다. 제목은 묘목이 아직 자라지 않은 왼쪽 하늘에 앉는다.
  해 원반은 위를 잘라 없앤다(다섯 개의 해가 줄지어 서면 반복 무늬가 된다).
- 스크린샷은 테두리, 그림자, 둥근 모서리 없이 같은 회색 무대에 놓는다. 앱 화면의 실제 모습과 같다.
- 호박색은 내려받기 버튼 하나에만 쓴다.
- 움직임은 한 번뿐: 처음 열 때 다섯 단계가 왼쪽부터 차례로 나타난다(나무가 한 번 자란다). `prefers-reduced-motion`이면 없다.
- 숫자는 모두 `docs/project-introduction.md`나 `README.md`에서 가져온다. 큰 숫자 타일 없이 문장과 표로 쓴다.
- 식은 KaTeX 대신 브라우저 내장 MathML로 쓴다. 외부 스크립트가 없다.

## 일반형 점검과 수정

첫 초안에서 다른 비슷한 페이지에도 나왔을 기본값과 바꾼 점:

1. **어두운 히어로 + 오른쪽에 빛나는 세계수 한 장 + 왼쪽 제목.** 어느 앱 소개에도 나오는 구성이다.
   바꿈: 히어로를 성장 띠로 만들고 제목을 묘목 위 하늘에 둔다. 세계수 밤 장면은 마지막 내려받기 띠로 옮겼다.
2. **"111 / 10% / 200MB" 큰 숫자 타일 줄과 그라디언트 강조.** 바꿈: 측정 결과는 출처 문장과 함께 평범한 두 열 표로.
3. **기술 7개를 아이콘 달린 같은 모양 카드로.** 바꿈: 카드 없이 데이터 흐름 한 줄과 정의 목록. Qt 클래스 이름이 제목 역할을 한다.
4. **거의 검정 바탕 + 형광 강조 하나.** 바꿈: 어두운 회색은 스크린샷 배경 값(`#303030`) 그대로이고 이미지가 있는 띠에만 쓴다. 읽는 구간은 청자 종이, 강조는 호박(동작)과 세이지(링크).
5. **크림 바탕 + 테라코타.** 앱 설계에서도 테라코타 화분을 청자로 바꿨다. 같은 이유로 종이도 청자로 했다.
6. **대문자 눈썹 라벨, 01/02/03 번호.** 없앴다. 번호는 실제 순서인 성장 단계(20~100%)에만.
7. **가운데 점으로 이은 메타 문자열, 버튼 끝의 화살표.** 문장으로 풀었다. 데이터 흐름 그림의 화살표만 남긴다(실제 흐름).
8. **KaTeX 스크립트와 글꼴.** MathML로 대체해 외부 자산을 Google Fonts 하나로 줄였다.

## 만들면서 고친 점과 뺀 장식

Edge headless로 1440px와 390px을 다섯 차례 찍어 보며 고쳤다.

- 1차: `object-fit: cover`는 좁은 칸에서 좌우만 자르고 위는 자르지 않아 해 원반의 빛번짐이 제목 아래에 떠 있었다.
  칸을 `overflow: hidden` 창으로 만들고 이미지를 `630 / 폭` 배율로 키워 바닥에 붙였다. 위쪽 240px(해)가 정확히 잘리고 나무가 1.3배 커졌다.
- 2차: 히어로(1600px)와 본문(1200px)의 왼쪽 선이 어긋나 같은 1600px 틀에 맞췄다. 그 대신 넓어진 상관계수 표, 기술 목록, 식 묶음은 1120px로 묶었다.
  MathML `display="block"`은 가운데 정렬이라 `displaystyle`만 남겨 왼쪽 정렬했고, exp 안의 빼기는 단항 연산자로 바꿨다.
  내려받기 띠 안의 바닥글 목록이 요구 사항 목록 스타일을 물려받아 어긋나던 것을 고쳤다.
- 3차: Edge headless는 창 폭을 504px 아래로 줄이지 않는다. 그래서 390px 확인은 폭 390px iframe으로 했다(504px 창에서 scrollWidth가 clientWidth와 같음을 따로 확인했고, 390px iframe 화면에서도 잘린 글자가 없었다).
  모바일 테마 캐러셀의 첫 칸이 여백 없이 붙어 `scroll-padding-inline`을 더했다. 데이터 흐름은 좁은 화면에서 세로(↓)로 바꿨다.
- **뺀 장식: 표 한 칸의 감색 강조("열매 수 1.00").** 열매 나무를 떠올리게 하려고 넣었지만, 표 안에서 한 구절만 다른 색으로 칠하는 일반형 습관이었고
  다른 다섯 줄보다 그 줄이 더 중요하다는 잘못된 신호를 줬다. 감색은 스크린샷 안의 감에게 맡긴다.
- 기억에 남는 한 가지(성장 띠)는 처음 열 때 다섯 단계가 왼쪽부터 화분에서 위로 차례로 드러나는 한 번의 움직임만 갖는다.
